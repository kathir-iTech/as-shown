## Workflow

1. Upload one authorized garment photograph. Choose tops/layers, bottoms, dresses/full looks or shoes. Images are decoded and a metadata-free preview input is prepared locally. Quick Try does not invent front/back views, condition declarations or an inspection.
2. Add an adult shopper photograph or deliberately select the synthetic sample. Approve the two selected inputs before transmission. Category-specific framing guidance is visible. Source evidence and buyer notes are withheld from YouCam.
3. The existing server verifies structural admission, image decoding, consent, current pricing and free-credit availability. Redis atomically binds category and input commitments to an intent and reserves the aggregate allowance. Actual YouCam submission and polling drive displayed states; there is no fabricated percentage or silent regeneration.
4. Inspect the real downloaded result beside the unchanged original. A generated look is never fit, size, identity, authenticity or condition evidence. Unknown condition remains explicitly unknown.
5. Keep notes/decisions and organize My Rack. Personal inputs remain memory-only. A separate unchecked control can retain a generated likeness on this device. Export a verified ZIP or standalone script-free readable HTML when a durable portable copy matters.
6. Sellers can create a full condition record with front/back photographs, a declaration and linked close-ups for each issue. Optional publication scrubs photo metadata into a separate seller-only revision and uses the existing bounded private Blob/Redis path. Personal looks and notes are excluded. Collections group up to eight existing seller read capabilities; each keeps its own expiry and revocation.

## Boundaries

- No paid dependency, external font service, new provider, account system, checkout, scraped stock or fictional live inventory. The three synthetic demos are optional examples.
- My Rack: 40 records / 100 MB of source photographs. Saved generated looks: separate 50 MB limit. Browser data can be cleared or evicted; exports are the portable fallback. Deletion requires confirmation and removes the item, notes, saved look and item recovery tokens from this device, not downloads, provider data or previously published copies.
- Existing 800-unit aggregate ceiling, 100-unit free reserve, price verification, rate limits, request recovery, private seller storage quotas, CSP and backwards package support remain. No balance counters or provider keys are reset.
- Provider category mapping follows [the official Clothes V3 reference](https://docs.makeupar.com/reference/ai_clothes/v3.0). Broader category handling does not establish real-user accuracy or usefulness.
- The ink / warm-white / vermilion interface prioritizes uploads and the working stage. Native transitions reveal photo changes, inspection zoom and actual task states, with reduced-motion behavior. No paid motion package is required.
